# Классификация данных PropDevelopment и риски

Классификация по ISO/IEC 27001 (A.8.2 Information classification) и ISO/IEC 27002:
публичные, внутренние, конфиденциальные, секретные.
Для персональных данных дополнительно указана категория по 152-ФЗ: ПДн, специальные категории ПДн.
Оценка риска: незначительный, значительный, критический.

## 1. Классификация данных

### Публичные

| Данные | Где обрабатываются |
|---|---|
| Каталог объектов: планировки, площади, цены, статус "свободно/забронировано" | Витрина продаж, client-mart-estate-app, публикация каталога [Kafka] |
| Публичные 3D-медиа онлайн-тура | client-tour-app |
| Объявления УК, графики плановых работ, тарифы ЖКУ | tenant-core-app, витрина для собственников, API УК |

### Внутренние

| Данные | Где обрабатываются |
|---|---|
| Логи, метрики, трассировки | Все контейнеры |
| Справочники и НСИ: типы объектов, статусы сделок, каталоги услуг | client-mart-*, tenant-core-app |
| Агрегированная BI-отчётность без ПДн | Хранилище данных, BI и отчётность |
| Контракты партнёрских API, схемы интеграций | Документация, tenant-core-app |

### Конфиденциальные

| Данные | Где обрабатываются |
|---|---|
| ПДн клиентов: Ф. И. О., телефон, e-mail из формы бронирования (ПДн по 152-ФЗ) | Витрина продаж -> client-crm-app -> crm-db |
| Расширенная форма клиента для сделки: паспорт, СНИЛС, состав семьи, доходы (ПДн по 152-ФЗ) | client-mart-app, client-mart-db |
| ПДн собственников, адрес, состав домохозяйства, лицевой счёт (ПДн по 152-ФЗ) | CRM (ЖКУ), crm-tenant-db |
| Данные онлайн-сделки: договоры, документы, суммы, стороны | client-mart-app, client-mart-db, СМЭВ [SOAP] |
| Записи онлайн-туров и результаты осмотров с привязкой к клиенту | client-tour-app, client-tour-db |
| Финансовая и бухгалтерская отчётность | accountant-service-1 и его БД |
| Сырые данные CDC со всех продуктовых БД | Хранилище данных [Greenplum], DWH [S3] |
| Данные ЖК и собственников партнёрских УК | tenant-core-app <-> API УК |

### Секретные

| Данные | Где обрабатываются |
|---|---|
| Учётные данные, хеши паролей, токены и сессии | auth-service-1 [Keycloak], auth-db-1 |
| Учётные записи сотрудников, группы, права | Active Directory (обе службы каталогов) |
| Секреты интеграций: ключи API УК, ключи платёжной системы, сертификаты СМЭВ, ЭП | tenant-core-app, client-mart-app |
| Технологические учётные записи и строки подключения [JDBC] | Все контейнеры |
| Платёжные реквизиты и транзакции по лицевым счетам ЖКУ | tenant-core-app, tenant-core-db, платёжная система |
| Биометрия и номера ТС новых сервисов "Умный дом" (специальная категория ПДн по 152-ФЗ) | Платформа партнёра, tenant-core-app |
| Ключи шифрования и резервные копии БД | ЦОД, арендованное облако |

## 2. Риски по категориям

### Публичные

| Данные | Риск | Обоснование | Оценка |
|---|---|---|---|
| Каталог объектов | Искажение | Витрина не имеет своей БД, каталог приходит из client-mart-estate-app без контроля целостности потока: подмена цены или статуса влияет на продажи | значительный |
| Каталог объектов | Некачественные данные | Данные о фонде дублируются в client-mart-estate-db, client-mart-db и DWH без единого владельца: расхождение статусов, бронирование проданного объекта | значительный |
| Объявления УК, тарифы | Искажение | Поступают из API УК без единых политик безопасности и контроля содержимого | значительный |
| 3D-медиа тура | Потеря | Восстанавливается повторной съёмкой, бизнес-процесс не останавливается | незначительный |
| Все публичные | Утечка | Данные предназначены для публикации, ущерба от раскрытия нет | незначительный |

### Внутренние

| Данные | Риск | Обоснование | Оценка |
|---|---|---|---|
| Логи, трассировки | Утечка | В логи попадают ПДн и токены, доступ к логам шире, чем к БД; внутренние потоки не контролируются системно | значительный |
| Контракты API, схемы интеграций | Утечка | Раскрытие контрактов, в которых уже выявлены избыточные ПДн и отсутствие проверки принадлежности объекта, упрощает атаку на эти API | значительный |
| Справочники, НСИ | Некачественные данные | Четыре домена ведут справочники независимо, единого владельца нет: рассинхронизация статусов и типов | значительный |
| BI-отчётность | Искажение | Строится на потоках CDC: частичная загрузка даёт неверные управленческие решения без явного признака сбоя | значительный |
| BI-отчётность | Обесценивание | Без управления потоками и каталога данных накопленный массив непригоден для BI-, ML- и AI-сервисов - блокирует новые продукты | значительный |
| Логи, метрики | Потеря | Не останавливает бизнес, но лишает возможности расследовать инцидент | незначительный |

### Конфиденциальные

| Данные | Риск | Обоснование | Оценка |
|---|---|---|---|
| ПДн клиентов | Утечка | Несколько несогласованных точек регистрации, со стороны систем обработки данных нет ограничений на доступ. Отображение чужого Ф. И. О. в личном кабинете - реализовавшаяся утечка ПДн. Ответственность по 152-ФЗ до 18 млн руб. при повторном нарушении | критический |
| ПДн клиентов и собственников | Искажение | Тот же дефект изоляции позволяет записать данные в чужой профиль: последствия для сделки и для начислений ЖКУ | критический |
| Расширенная форма клиента | Утечка | Наиболее чувствительный набор ПДн: собирается витриной, переиспользуется в сделке, реплицируется в DWH через CDC - единого периметра защиты нет | критический |
| Данные онлайн-сделки | Потеря | Юридически значимый процесс с интеграцией в госорганы: утрата документов срывает регистрацию. Резервные копии БД не покрывают целостность распределённого процесса client-mart-app <-> СМЭВ <-> accountant-service-1 | критический |
| Данные онлайн-сделки | Искажение | Подмена сумм, реквизитов или сторон ведёт к финансовому ущербу и недействительности регистрационных действий; контроля целостности межсистемных потоков нет | критический |
| Данные ЖК партнёров | Утечка | Нет проверки принадлежности объекта запрашивающей УК; риск масштабируется с числом партнёров | критический |
| Сырые данные CDC в Хранилище и DWH | Утечка | DWH концентрирует реплики ПДн всех продуктовых БД, обезличивание и маскирование не применяются, доступ есть у аналитиков BI: одна точка компромисса открывает весь массив | критический |
| Сырые данные CDC | Некачественные данные | Потоки CDC не контролируются, схемы источников меняются командами независимо: деградация витрин | значительный |
| Финансовая отчётность | Искажение | Работа под чужими учётными записями не позволяет установить авторство изменения проводок: недостоверная отчётность, налоговые последствия | критический |
| Финансовая отчётность | Утечка | Домен "Финансы" имеет отдельную службу каталогов, но единых политик доступа по компании нет | значительный |
| Записи онлайн-туров | Утечка | Запись связана с клиентом и объектом (факт интереса к покупке, состав семьи в кадре), отдельной политики доступа к client-tour-db нет | значительный |
| Данные Хранилища | Обесценивание | Без каталога данных, владельцев и правил доступа массив нельзя использовать для новых сервисов | значительный |
| Все конфиденциальные | Потеря | Резервное копирование БД выполняется на глубину, достаточную для восстановления - компенсирующая мера действует | значительный |

### Секретные

| Данные | Риск | Обоснование | Оценка |
|---|---|---|---|
| Учётные данные и токены auth-service-1 | Утечка | Один сервис аутентификации обслуживает клиентов и собственников: компрометация auth-db-1 открывает обе витрины и все ПДн за ними | критический |
| Учётные записи в Active Directory | Утечка | AD обслуживает бизнес-системы, обработку данных и финансы: компрометация даёт контроль над IT-ландшафтом | критический |
| Права доступа в Active Directory | Искажение | Изменение членства в группах расширяет права незаметно; специалисту по ИБ передают не все изменения | критический |
| Секреты интеграций | Утечка | Интеграции с УК и госорганами построены без единых политик; ключ позволяет действовать от имени PropDevelopment в юридически значимых процессах | критический |
| Технологические учётные записи, строки подключения | Утечка | Сервисы обращаются к БД напрямую по JDBC; хранение секретов в секрет-менеджере и ротация не предусмотрены | критический |
| Биометрия и номера ТС | Утечка | Специальная категория ПДн: биометрию нельзя заменить, как пароль. Обработка на стороне партнёра требует правовой и технической рамки до запуска сервисов "Умный дом" | критический |
| Платёжные реквизиты и транзакции ЖКУ | Утечка | Контракты API УК позволяют партнёру видеть данные клиентов другой УК: межарендаторная утечка заложена в контракте | критический |
| Платёжные реквизиты и транзакции ЖКУ | Искажение | Контракты позволяют внешнему пользователю изменять данные, к которым нет доступа, в том числе начисления по чужим лицевым счетам | критический |
| Ключи шифрования и резервные копии | Утечка | Копии содержат полные срезы ПДн, частично размещены в арендованном облаке | критический |
| Ключи шифрования | Потеря | Утрата ключа делает резервную копию непригодной для восстановления - отказ компенсирующей меры | критический |
| Все секретные | Некачественные данные, обесценивание | Ценность определяется конфиденциальностью и актуальностью, а не аналитической пригодностью; значим только эффект неротируемых секретов | незначительный |
