# Проверочный лист безопасности бизнес-систем PropDevelopment

Заполнено по описанию компании и диаграмме контейнеров.
**Да** - мера реализована, **Нет** - не реализована, **Частично** - не для всех систем,
**Н/д** - данных в описании недостаточно, вопрос выносится на интервью в ходе аудита.

Обоснование состава разделов - в [`sections-rationale.md`](./sections-rationale.md).

## I. Управление доступом

| № | Вопрос | Да/нет | Комментарий |
|---|---|---|---|
| 1 | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | Нет | auth-service-1 [Keycloak] обслуживает клиентов и собственников, MFA не описана. Для менеджеров и бизнес-аналитиков вход через Active Directory без MFA |
| 2 | Настроены ли требования к сложности паролей и их регулярное обновление? | Н/д | Политика паролей не описана. Keycloak и AD поддерживают такие политики - проверить фактические настройки |
| 3 | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | Нет | Специалист по ИБ один на компанию, процесс передачи ему изменений нарушен. Регулярный пересмотр не описан |
| 4 | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Нет | Со стороны систем обработки данных ограничений на доступ к данным нет. Аналитики BI имеют доступ к хранилищу, содержащему ПДн всех систем |
| 5 | Автоматически ли удаляются или деактивируются учётные записи после увольнения или изменения должности сотрудников? | Н/д | Процесс не описан. Проверить связку кадровых процессов с Active Directory |
| 6 | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | Частично | Приложения ведут логи, но централизованный сбор и разграничение доступа к журналам не описаны. Инцидент с чужими ПДн выявлен по жалобам клиентов, а не по журналам |
| 7 | Используются ли механизмы контроля доступа на основе атрибутов (ABAC) для повышения гибкости управления доступом? | Нет | Модель ABAC не применяется. Для мультиарендной модели ЖКУ нужен атрибут принадлежности объекта к УК |
| 8 | Используются ли системы аутентификации пользователей для доступа к системам? | Да | Внешние пользователи - auth-service-1 [Keycloak]; сотрудники - Active Directory (две службы каталогов) |
| 9 | Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными? | Частично | Отдельный контур выделен только для домена "Финансы" - своя служба каталогов. Контуры для ПДн и хранилища данных не выделены |
| 10 | Ограничен ли доступ к системам из внешних источников? | Частично | Доступ внешних пользователей идёт через firewall, но доступ партнёрских систем к API не ограничен политиками |
| 11 | Ведётся ли единый реестр учётных записей? | Нет | Учётные записи разнесены: auth-db-1, две службы Active Directory. Единого реестра нет |
| 12 | Используются ли средства управления учётными записями на базе единого реестра? | Нет | Централизованного IdM/IGA-решения нет, управление ведётся раздельно по службам каталогов |
| 13 | Применяются ли средства для отзыва прав доступа? | Частично | Штатные средства Keycloak и Active Directory доступны, автоматизированный процесс отзыва не описан |
| 14 | Используются ли средства централизованного контроля доступа? | Нет | Каждый продукт реализует авторизацию самостоятельно. Централизованного шлюза или PDP нет |
| 15 | Проверяет ли система принадлежность запрашиваемого объекта правам пользователя (изоляция арендаторов)? | Нет | Клиент видит в личном кабинете данные другого клиента; партнёр из одной УК видит и изменяет данные другой УК. Проверка владения объектом отсутствует |
| 16 | Разделены ли роли пользователей и технологических учётных записей сервисов? | Н/д | Сервисы обращаются к БД напрямую [JDBC]; выделение и учёт технологических учётных записей не описаны |
| 17 | Применяется ли выдача временных привилегий (JIT) для административных задач? | Нет | Не описано. Постоянные привилегии администраторов повышают риск при работе под чужой учётной записью |

|---|---|---|---|

| 2 | Используется ли шифрование на уровне базы данных, файловой системы и при передаче данных по сети? | Н/д | Не описано ни для БД, ни для CDC-потоков, ни для резервных копий в арендованном облаке |

| 5 | Выполняется ли регулярное тестирование процесса восстановления данных из резервных копий? | Н/д | Тестирование восстановления не описано. Заявлена только глубина копирования |
| 6 | Ограничен ли доступ к резервным копиям данных, и зашифрованы ли они? | Н/д | Не описано. Часть мощностей арендована у облачного провайдера - требует отдельной проверки |
| 7 | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных? | Нет | Несколько несогласованных точек регистрации клиента, единого учёта ПДн нет. Расширенная форма клиента переиспользуется другими системами |
| 8 | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности? | Нет | Метки безопасности и мониторинг по классам данных не применяются |
| 9 | Разработаны ли процессы и системы Data Governance для управления данными? | Нет | Внутренние потоки данных между продуктами не контролируются системно. Отсутствие управления потоками названо блокером новых продуктов на данных |
| 10 | Реализованы ли системы или процессы безопасного уничтожения данных? | Н/д | Процедуры удаления по истечении срока обработки и по отзыву согласия не описаны |
| 11 | Используются ли системы или процессы контроля целостности данных? | Нет | Каталог передаётся из client-mart-estate-app в витрину, данные реплицируются через CDC - контроль целостности потоков не описан |
| 12 | Реализованы ли системы или процессы контроля сохранности данных? | Частично | Обеспечивается резервным копированием, отдельных процессов контроля сохранности нет |
| 13 | Применяются ли средства или процессы анонимизации данных? | Нет | Хранилище содержит сырые данные CDC с ПДн, обезличивание и маскирование не применяются |
| 14 | Разработана ли инструкция по процессу восстановления данных? | Н/д | Не описана. Для распределённой онлайн-сделки (client-mart-app, СМЭВ, accountant-service-1) требуется отдельный порядок восстановления |
| 15 | Ограничен ли состав данных, передаваемых в аналитическое хранилище через CDC? | Нет | В хранилище передаются сырые данные всех продуктовых БД без фильтрации состава |
| 16 | Исключены ли ПДн, пароли и токены из журналов приложений? | Н/д | Маскирование чувствительных данных в логах не описано; доступ к логам шире, чем к БД |
